## Работа с компонентами

### Локальность и переиспользование

- Утилиты, хуки, типы и внутренние компоненты страницы остаются рядом с ней. Принадлежность одной странице важнее числа использований внутри неё.
- Конвертеры DTO принадлежат странице или бизнес-компоненту-потребителю. Не выноси их в lib, services, store и не объединяй лишь из-за совпадения кода.
- Переиспользуемый целиком сценарий переносится в business pattern или feature вместе с поведением и преобразованиями.
- Общие низкоуровневые функции без знания DTO и формы могут находиться в lib.
- Общие хуки в lib не импортируют services/store. Сервисные хуки получения DTO живут в services; хуки сценария — у его потребителя.

### Выбор UI и бизнес-компонента

- Foundation: глобальные стили и токены.
- Atoms: классы и стили примитивов; никаких production React-обёрток ради variant.
- Molecules: небольшие UI-композиции (TextField, LoadingButton).
- Organisms: Table, Pagination с вычислением видимых страниц, многоточий и переходов. Внутренняя UI-логика допустима; внешними операциями они не управляют.
- Patterns: DataGrid объединяет Table и Pagination, вызывает переданный `loadData` и управляет загрузкой/ошибками/результатом. Одна лишь композиция UI без управления операцией остаётся UI.
- Features: конкретный бизнес-сценарий, которому разрешены services/store; ProductsGrid подключает сервис товаров и настраивает DataGrid.
- Наличие callback или store-импорта само по себе не определяет категорию. Полный контракт и примеры: [границы компонентов](ProjectStructure.full.md#граница-organisms-patterns-и-features).

- Не экспортируй внутренние хуки, утилиты, константы, тесты, stories.

## Конвертация данных

Основной контракт: [DTO vs внутренние модели](ProjectStructure.full.md#dto-vs-внутренние-модели).

- Входящее преобразование: `{entity}FromDto.ts`; исходящее: `{entity}ToDto.ts`. Например, `app/cardEditPage/utils/cardFromDto.ts`.
- Каждая страница преобразует DTO под собственные требования. Совпадающие преобразования разных страниц не объединяются автоматически.
- В business-компоненте конвертер остаётся внутри его модуля, например `components/business/features/product/productEditor/utils/productToDto.ts`.
- Services принимают/возвращают DTO и могут валидировать внешний контракт. React Query/SWR-интеграция внутри services допустима, преобразование под сценарий туда не переносится.
- Store не импортирует services и DTO-типы. Страница/feature может передать в него внутреннюю модель, собранную из внешних данных.
- Pattern может принимать DTO и операции через props и импортировать только необходимые DTO-типы; исполняемые сервисы/store он не подключает.
- Не передавай функции-хуки через props. Обычные операции-callbacks и результаты хуков допустимы.

## Рефакторинг

- **Перед изменением существующего кода** — проверь dependency rules в ProjectStructure.md. Не нарушай границы слоёв.
- **При переносе файла** — проверь, что импорты в других файлах не сломались.
- **При добавлении нового импорта** — убедись, что он разрешён dependency rules (таблица запрещённых зависимостей).
- **Не предлагай FSD** (Feature-Sliced Design) — проект использует свою архитектуру, описанную в ProjectStructure.md.
- **Не используй `export default`** — только именованный экспорт.
